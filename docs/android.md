# 안드로이드 앱

웹에서는 저장 위치를 정할 수 없습니다 — 안드로이드 크롬에 File System Access API가
없어 다운로드 폴더로만 떨어집니다. `android/`의 WebView 앱은 그 부분만 네이티브로
처리합니다. 받은 파일은 **앱 데이터 폴더**에 회차별 하위 폴더로 들어갑니다.

```
Android/data/kr.gijul.direct/files/
  2026 7월 학평(인천) 생명과학Ⅰ/
      … 문제.pdf   … 정답.png   … 해설.pdf
```

권한을 물을 필요가 없고, 앱을 지우면 함께 정리됩니다. 대신 **안드로이드 11+에서는
다른 파일 관리자가 이 경로를 열 수 없으므로**, 앱이 목록과 열기를 직접 제공합니다 —
회차 목록 위의 **받아둔 자료** 버튼입니다. 열기는 FileProvider로 `content://` 를 넘겨
기기의 PDF 뷰어를 띄웁니다.

페이지는 `window.GijulNative`가 있을 때만 이 경로를 씁니다. **다른 OS·브라우저는 그대로**
다운로드로 저장되고, 받아둔 자료 버튼도 나타나지 않습니다.

## 문제지 읽기

문제·정답·해설은 **앱 안에서 엽니다.** WebView에는 PDF 뷰어가 없어 처음에는 기본
브라우저로 넘겼는데, 자료를 열 때마다 앱이 크롬으로 바뀌는 건 이 앱의 요점을 잃는
일이었습니다. `PdfRenderer`로 직접 그립니다 — 페이지는 `RecyclerView`로 필요한 것만
그리고(20쪽짜리를 통째로 비트맵으로 들면 메모리가 남아나지 않습니다), 확대는 다시
그리지 않고 뷰 변형으로 처리해 손가락을 따라옵니다. 정답은 PNG라 한 장으로 보여줍니다.

흔한 PDF 뷰어들이 쓰는 두 겹 구조를 따랐습니다.

| | 무엇을 | 어떤 크기로 |
|---|---|---|
| **밑그림** | 열 때 전 쪽 한 번 | 280px 고정 (장당 0.45MB) |
| **본그림** | 보는 쪽과 바로 앞뒤만 | **화면에 놓일 크기와 1:1** |

두 번째 줄이 핵심입니다. 표시될 폭보다 작게 그리면 늘려서 붙이게 되고 그것은 결국 흐린
화면입니다. 그래서 **메모리가 모자랄 때 낮추는 것은 해상도가 아니라 들고 있는 장수**
입니다. 확대는 손짓 도중에는 뷰 변형으로 따라가고, 손을 뗀 뒤 그 배율로 다시 그립니다.

고해상도를 보이는 쪽에만 쓰는 것도 같은 이유입니다 — 한 장이 수십 MB인 마당에 멀리까지
미리 그려봐야 서로를 밀어낼 뿐이고, 나머지 쪽은 밑그림이 즉시 받아 줍니다.

**축소는 1배 아래로도** 내려가 양옆에 여백이 생기며, 그만큼 여러 쪽이 한눈에
들어옵니다. 확대·축소는 손가락 사이를 중심으로 돌고, 여백이 생겨 가운데로 세워야
할 때는 손을 뗀 뒤에 합니다 — 손짓 중에 정렬하면 화면이 손에서 미끄러집니다.

화면에는 현재 쪽(`3 / 16`)과 배율이 뜹니다. 배율을 누르면 **폭 맞춤 ↔ 쪽 맞춤**을
오갑니다 — 문항을 읽을 때와 한 쪽을 통째로 훑을 때가 서로 다른 배율입니다.
**가리기**를 누르거나 화면을 한 번 두드리면 막대와 시스템 표시줄이 사라지고, 다시
두드리면 돌아옵니다. 뒤쪽까지 내려가면 **맨 위로** 단추가 나타납니다.

### 스크롤 막대

오른쪽 가장자리의 짧은 알약 하나입니다. **길이는 쪽수와 상관없이 고정**인데,
'얼마나 남았는가'는 잡았을 때 뜨는 말풍선이 `13 / 20`으로 말해 주므로 막대까지
길이로 되풀이할 것이 없어서입니다. 잡으면 4dp에서 9dp로 두툼해집니다.

흰 테를 먼저 깔고 먹을 얹습니다. 이건 문제지 **위에** 얹히는 것이라 그림이나
표처럼 검은 자리에 걸리면 먹만으로는 묻힙니다 — ㄴ자 손잡이가 안 보였던 그
일입니다. 어느 바탕이든 둘 중 하나는 보입니다.

보이는 굵기는 4dp지만 **잡히는 폭은 22dp**입니다. 4dp를 손가락으로 겨누게 하면
대개 빗나갑니다. 알약 밖을 누르면 그 자리로 먼저 뜁니다.

말풍선을 막대 **왼쪽**에 붙이는 것은 위에 얹으면 잡은 손가락에 가려서입니다.
위 막대의 쪽수 표시와 겹치는 것 같지만, 그쪽은 화면을 두드려 감추면 함께
사라집니다. 훑는 동안 쪽수를 알려주는 것은 이것뿐입니다.

값은 `FloatService.SB_*` 한 곳에 있고 뷰어가 그것을 가져다 씁니다. 띄워 둔 창의
막대와 뷰어의 막대는 같은 것이어야 합니다.

이미 받아둔 자료에 같은 파일이 있으면 그걸 씁니다. 필기 앱·인쇄로 넘길 때를 위해
화면 위의 **다른 앱** 버튼을 남겨뒀습니다. EBSi 사이트 링크처럼 자료가 아닌 주소는
그대로 브라우저 몫입니다.

앱은 사이트를 그대로 불러오므로 페이지를 고쳐도 APK를 다시 만들 필요가 없습니다.

창 크기와 자리는 **한 번 맞추면 그대로 남습니다**. 두 벌로 적습니다 — 화면 크기를
열쇠에 넣은 한 벌이 있어서 세로에서 맞춘 것은 세로에서, 가로에서 맞춘 것은
가로에서 제 크기로 돌아옵니다. 그리고 열쇠 없는 **마지막 한 벌**이 따로 있어,
처음 보는 화면(처음 돌려 본 가로, 바꾼 폰)에서도 기본값이 아니라 마지막 크기를
화면에 맞게 줄여 씁니다. 빌려 온 크기일 때는 자리까지 빌리지 않고 가운데에
놓습니다.

## 띄워 두기

뷰어의 **띄우기**를 누르면 문제지가 다른 앱 위에 얹힙니다(`FloatService`,
안드로이드 8.0부터·'다른 앱 위에 표시' 권한). 필기 앱을 쓰면서 문제지를 곁에
두려는 것이 요점이라, 기본은 **터치가 그대로 밑으로 통과하는** 상태입니다.

**띄우면 앱은 물러납니다**(`finishAndRemoveTask`). 요점이 '다른 앱을 쓰면서
문제지를 곁에 두는 것'이라 뒤에 우리 화면이 남으면 그 앱으로 가는 데 한 걸음이
더 듭니다. 되부르는 길은 아래 ☰ 항목에 있습니다.

창은 셋으로 나뉩니다 — 위의 조작 바, 종이, 좌하단의 ㄴ자 손잡이. 바에서 통과와
조작을 오가고, 슬라이더로 투명도를 정합니다. 확대는 조작일 때 손가락 둘로 하고,
크기는 손잡이로 바꿉니다. 자판이 뜨면 손잡이는 물러납니다 — 대개 자판 위에
겹쳐 앉아, 글자를 치는 내내 걸리적거립니다.

오른쪽 끝의 **－** 는 창을 접습니다. 종이도 손잡이도 사라지고 바에는 **≡ ＋ ✕**
만 남아 118dp짜리 알약이 됩니다 — 종이가 없는데 투명도와 통과 여부를 물어봐야
소용이 없습니다. **≡** 는 잡는 자국입니다. 바 전체가 손잡이라 아무 데나 잡아도
되지만, 단추를 빼고 남는 빈자리가 한 칸뿐이라 그 한 칸을 눈에 보이게 둡니다.
남의 앱 위에 알약 하나만 뜨므로 **흰 테**를 둘러 묻히지 않게 합니다.

알약은 창의 **오른쪽 끝**, 곧 방금 그 두 단추가 있던 자리에 그대로 섭니다. 두
단추의 화면 좌표가 접기 전후로 같아서 눌린 손가락 밑에서 단추가 달아나지
않습니다.

접힘은 **0에서 1까지 이어지는 값 하나**(`foldT`)로 굴러갑니다. 자리도 폭도 종이의
투명도도 거기서 나오므로 중간 자리가 다 있습니다. 전에는 폭과 자리를 한 번에
갈아 끼워서, 알약이 오른쪽 끝에 이미 가 있고 그제서야 나머지가 정리되니 창이
순간이동한 뒤에 움직이는 것처럼 보였습니다. `wx` 는 언제나 **펼친 창의 왼쪽 변**
이고, 알약이 오른쪽에 서는 것은 그리는 쪽에서 밀어 주는 것뿐입니다 — 접은 채로
돌리든 옮기든 셈이 한 곳에서만 납니다. 다른 앱을 잠깐 통째로 봐야 할 때 닫았다 다시 띄우면
보던 자리와 배율을 잃는데, 접으면 그대로 있다가 **＋** 로 그 자리에 돌아옵니다.
창을 지우지 않고 보이기만 끄는 것이라 종이는 열린 채 남습니다.

**투명도는 통과일 때 스스로 깎입니다.** 안드로이드 12부터 창이 흐릿하게 겹쳐
있으면 그 아래로 가는 터치를 시스템이 통째로 버립니다(합친 불투명도 0.8이 상한,
`InputManager.getMaximumObscuringOpacityForTouch()`). 그래서 통과일 때는 그 값까지만
올리고, 조작으로 바꾸면 정한 값이 그대로 돌아옵니다.

### 목록

바 왼쪽의 **☰** 는 종이 자리에 문서 목록을 띄웁니다(`PickerView`). 보던 회차의
다른 자료뿐 아니라 **전체 목록**을 훑을 수 있어서, 앱으로 돌아가지 않고도 다음
문제지로 넘어갑니다. 화면은 둘뿐입니다 — 과목 고르기와 회차 고르기.

처음 열면 **보고 있던 과목의 회차부터** 펼칩니다. 찾던 것은 대개 거기 있고,
아니면 '‹' 한 걸음이 전체 목록입니다. 어느 과목에서 왔는지는 페이지가 알려
줍니다(`openPaperIn`) — 주소만으로는 알 수 없습니다. 회차 파일이 과목마다 따로라
주소 하나가 어느 과목 것인지 되짚으려면 과목 파일을 전부 받아 뒤져야 합니다.
과목 페이지(`s/`)는 제 주소에서 읽습니다. 그 창구가 없는 옛 앱은 옛 길로
그대로 가고 전체 목록에서 시작합니다 — 인자를 더 붙인 채로 부르면 맞는 메서드가
없어 호출이 통째로 실패하는데, 페이지는 앱보다 먼저 갱신되므로 그 사이 자료가
아예 안 열립니다.

그 값이 없을 때는 **자료 이름에서 되짚습니다**(`Catalog.byTitle`). 받아둔 자료에서
띄웠거나 아직 옛 페이지가 캐시에 남아 있으면 이쪽이 받습니다 — "2026 6월 모평
생명과학Ⅰ 문제.pdf" 같은 이름에는 과목이 그대로 들어 있습니다. 겹치면 긴 이름이
이깁니다('수학'은 '수학Ⅰ'에 묻힙니다). 학년은 이름에 없어 고3부터 봅니다.

전체 목록을 보는 중에 **☰ 를 3초 누르면 앱 화면이 열립니다**. 띄우면 앱이
물러나므로 되부를 길이 하나는 있어야 하는데, 44dp 바에 단추를 더 놓을 자리가
없어 몸짓으로 두었습니다. 목록의 맨 위는 사람이 '더 넓은 데서 고르고 싶다'고
느끼는 바로 그 자리입니다. 몇 초 남았는지 숫자로 알립니다 — 표시가 없으면 3초는
'안 되는 것'과 구별되지 않습니다. 앱을 부르면 창은 접혀서 물러납니다. 문제·정답·해설은
셋째 화면으로 빼지 않고 회차 줄에 바로 붙였습니다. 좁은 창에서 한 걸음은 큽니다.

목록은 새로 만들지 않았습니다. 사이트가 이미 `data/`로 같은 자료를 정적 파일로
내보내고 있어, 색인 하나(36KB)와 과목 파일 하나(1~69KB)만 받으면 됩니다
(`Catalog`). 검색은 색인의 `aliases`를 그대로 써서 '언매'·'생윤'이 걸리고,
띄어쓰기를 지우므로 '고3생명'처럼 물어도 됩니다.

**내려받기 통로는 둘입니다.** `MainActivity.download`는 EBSi 주소만 받습니다 —
문제지를 받는 길이 아무 데나 열리지 않게 막아 둔 것이라 넓히지 않습니다. 그래서
목록은 **우리 사이트만** 받는 좁은 통로를 따로 씁니다. 좁은 문 둘이 넓은 문
하나보다 낫습니다. 스쳐 간 문제지는 캐시 폴더에 스물넉 장까지만 남습니다.

## 뒤로가기

한 번 누르면 **화면에 열어 둔 것 하나가 닫힙니다.** 위에 덮인 것부터입니다 —
크게 보기 → 시트(보내기·받아둔 자료·AI로 쓰기·갱신 내역) → 알림 막대 →
내 과목 편집. 닫을 것이 없으면 방문 기록을 되짚고, 그것도 없을 때에만
**한 번 더 눌러야** 앱이 닫힙니다.

무엇을 닫았는지는 앱이 판단하지 않습니다. 페이지의 `window.gijulBack()`이 하나를
닫고 그 사실을 돌려주며, 앱은 그 답이 거짓일 때만 다음 단계로 갑니다. 화면에
새 겹판을 더할 때는 그 함수에 한 줄을 더하면 됩니다 — 앱은 고치지 않아도 됩니다.

닫는 동작은 **종료 수를 세지 않습니다.** 무언가 닫혔거나 기록을 되짚었으면 '한 번
더' 대기가 풀립니다. 그러지 않으면 시트를 닫은 다음 누른 뒤로가기가 곧장 종료로
이어져, 닫는 동작이 종료의 첫 번째 누름을 대신하는 꼴이 됩니다.

알림 막대는 **답 없이 거둡니다.** 뒤로가기는 '지금은 됐다'는 뜻이지 '아니오'가
아니어서, '아니오'로 처리하면 앱 설치 권유를 뒤로가기로 넘긴 사람에게 다시는
묻지 않게 됩니다.

## 앱 자체 업데이트

껍데기(WebView 바깥의 네이티브 부분)를 고칠 때만 APK가 새로 필요한데, 스토어를
거치지 않으니 알려줄 주체가 없습니다. 그래서 **명세를 사이트에 같이 올려두고 앱이
직접 읽습니다.**

```
app/latest.json        versionCode·versionName·url·size·sha256·notes
```

APK 자체는 저장소가 아니라 **GitHub 릴리스 자산**으로 나갑니다. 판본마다 1.8MB가
히스토리에 영구히 쌓이면 받는 사람 전부가 그 비용을 내기 때문입니다. `android.yml`이
서명해 빌드한 APK를 `versionName`으로 태그를 달아 릴리스에 붙입니다.

```
릴리스에 붙는 이름   gijul-direct.apk           (늘 같습니다)
사람이 누르는 주소   …/releases/latest/download/gijul-direct.apk
latest.json 의 url   …/releases/download/v4.8/gijul-direct.apk
```

아래쪽은 **판본을 못박습니다.** `latest.json`은 한 판본을 가리키는 문서라, 주소만
`latest`로 두면 다음 판이 올라간 순간 거기 적힌 크기·sha256과 실제로 내려오는
파일이 어긋나고 앱이 설치를 거부합니다.

앱은 **실행할 때마다**, 그리고 다시 앞으로 불러올 때마다 이 명세를 보고, 설치된
versionCode보다 크면 알림 막대를 띄웁니다. 누르면 받아서 시스템 설치 화면으로
넘깁니다. 새 버전이 없으면 아무 말도 하지 않습니다 — 그래야 매번 확인해도 됩니다.

설치 화면을 띄우기 **전에** 받은 파일을 직접 열어 세 가지를 확인합니다 — SHA-256이
명세와 같은지, 패키지 이름이 우리 것인지, **서명 인증서가 지금 실행 중인 앱과
같은지.** 세 번째는 안드로이드도 강제하지만 그건 설치 화면이 뜬 뒤의 일이라, 그
앞에서 먼저 거릅니다. 그래서 **서명 키가 바뀌면 기기가 업데이트를 거부합니다.**

안드로이드 8+에서는 이 앱에 "이 출처 허용"을 한 번 줘야 하며, 없으면 앱이 해당
설정 화면으로 안내합니다.

## 새 판본 내보내기

`android/app/build.gradle`의 `versionCode`와 `versionName`을 올려 main에 밀면
끝입니다. 나머지는 `android.yml`이 합니다 — 시크릿의 키로 서명해 빌드하고,
**지문이 이전 판본과 같은지 확인하고**, 릴리스를 만들어 APK를 붙이고,
`app/latest.json`을 커밋합니다.

차례가 정해져 있습니다. **릴리스를 먼저 만들고 명세를 나중에 커밋합니다** —
반대로 하면 명세가 아직 없는 주소를 가리키는 동안 앱이 그것을 읽고 내려받기에
실패합니다. versionCode가 늘지 않았으면 거기서 조용히 멈춥니다.

사용자의 알림 막대에 뜰 한 줄은 **커밋 본문의 `Notes:` 줄**에서 가져옵니다.

```
Release 4.9

Notes: 문제지를 넘길 때 쪽 번호를 함께 보냅니다
```

그 줄이 없으면 "앱을 새로 고쳤습니다"로 갑니다. 커밋 제목은 영어 관례라 그것을
쓰면 화면에 "Release 4.9"가 나가므로, 제목을 그대로 가져다 쓰지 않습니다.

손에서 명세만 확인하고 싶다면 `python3 tools/publish_apk.py --notes "…"`가
`app/latest.json`을 써 줍니다. 다만 릴리스 자산을 올리는 것은 워크플로 몫이라,
그것만으로는 배포가 끝나지 않습니다.

### 서명 지문 확인

`android.yml`은 서명한 APK의 인증서를 `docs/assetlinks.json`의 지문과 대조하고,
다르면 **거기서 멈춥니다.** 서명 키가 바뀐 APK는 기존 기기가 영영 거부하므로
(지우고 새로 깔아야 하며 받아둔 자료도 사라집니다), 나가기 전에 막습니다.

```
Release 4.9

Notes: 문제지를 넘길 때 쪽 번호를 함께 보냅니다
```

그 줄이 없으면 "앱을 새로 고쳤습니다"로 갑니다. 커밋 제목은 영어 관례라 그것을
쓰면 화면에 "Release 4.9"가 나가므로, 제목을 그대로 가져다 쓰지 않습니다.

## 빌드

Actions의 **APK 빌드** 워크플로를 수동 실행하면 artifact로 받을 수 있습니다.
직접 빌드하려면:

```bash
cd android
echo "sdk.dir=$ANDROID_HOME" > local.properties
gradle assembleDebug        # app/build/outputs/apk/debug/app-debug.apk
```

설치할 때 "출처를 알 수 없는 앱"을 허용해야 합니다.

## 릴리스 서명

릴리스 빌드는 저장소에 없는 키로 서명합니다. 키를 만들고 `android/keystore.properties`에
경로·비밀번호를 적어두면 `assembleRelease`가 그걸 씁니다 (둘 다 gitignore 대상입니다).

```bash
cd android
keytool -genkeypair -v -keystore gijul-release.jks -alias gijul \
  -keyalg RSA -keysize 4096 -validity 10000
cat > keystore.properties <<'EOF'
storeFile=gijul-release.jks
storePassword=…
keyAlias=gijul
keyPassword=…
EOF
gradle assembleRelease
```

CI에서 빌드하려면 저장소 시크릿에 `KEYSTORE_BASE64`(키를 base64로 인코딩한 값),
`KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`를 넣습니다. 시크릿이 없으면 디버그로 빌드합니다.

**서명 키를 바꾸면 기존 앱 위에 덮어쓸 수 없습니다.** 지우고 새로 설치해야 하며 받아둔 자료도
사라집니다. 자체 업데이트도 서명이 다르면 설치 전에 스스로 멈춥니다. 키를 잃어버리면 같은
서명으로 업데이트할 방법이 영영 없으니, 저장소 밖에 따로 보관하세요.

## 링크를 앱으로 받기

앱이 사이트 주소를 받도록 등록해 두었습니다(`AndroidManifest.xml`의 VIEW 인텐트 필터).
그런데 **안드로이드가 그 등록을 인정하려면 도메인 뿌리에 확인 파일이 있어야 합니다.**

```
https://mangom72.github.io/.well-known/assetlinks.json
```

경로가 아니라 **뿌리**입니다. 이 저장소는 프로젝트 페이지라 `/Direct-mogo/` 아래에만
파일을 놓을 수 있어서, 저 자리는 **사용자 페이지 저장소**의 몫입니다.

### 한 번만 하면 되는 절차

**1. `mangom72/mangom72.github.io` 저장소가 있는지 확인합니다.**
   없으면 새로 만듭니다 — 이름이 정확히 `mangom72.github.io`여야 사용자 페이지가 됩니다.
   Public, README 하나로 시작해도 됩니다.

**2. 그 저장소에 파일을 놓습니다.** 경로와 이름이 정확해야 합니다.

```
mangom72.github.io/
  .well-known/
    assetlinks.json      ← 이 저장소의 docs/assetlinks.json 을 그대로 복사
```

내용은 [`assetlinks.json`](assetlinks.json)에 서명 지문까지 채워 두었습니다.
`.well-known` 앞의 점을 빠뜨리지 마세요.

**3. Pages를 켭니다.** Settings → Pages → Source를 `main` / `/ (root)`로.
   사용자 페이지는 보통 자동으로 켜집니다.

**4. 실제로 내려오는지 봅니다.** 이게 안 되면 아래는 전부 무의미합니다.

```bash
curl -i https://mangom72.github.io/.well-known/assetlinks.json
```

`200`과 JSON 본문이 나와야 합니다. `404`면 경로나 Pages 설정이 틀린 것입니다.
`Content-Type`은 `application/json`이 아니어도 동작합니다.

**5. 기기에서 다시 확인시킵니다.** 앱을 새로 설치하면 자동으로 수행되지만, 이미 설치되어 있는 경우에는:

```bash
adb shell pm verify-app-links --re-verify kr.gijul.direct
adb shell pm get-app-links kr.gijul.direct
```

마지막 줄이 `mangom72.github.io: verified` 로 바뀌면 끝입니다.
`none`이나 `1024`(확인 실패)면 4번이 제대로 안 된 것입니다.

### 확인이 안 돼도 쓸 수 있습니다

**설정 → 앱 → 기출 직행 → 기본으로 열기 → 지원되는 링크 열기**를 켜면
확인 없이도 링크가 앱으로 갑니다. 기기마다 한 번씩 해야 합니다.

페이지 쪽에도 길이 있습니다. 안드로이드 브라우저로 열면 각주에 **앱으로 열기**가
나타나고, 누르면 `intent:`로 앱을 두드립니다 — 깔려 있으면 열리고, 없으면 APK
내려받기로 갑니다.

**페이지가 스스로 넘기지는 않습니다.** 예전에는 안드로이드로 보이면 곧장 `intent:`로
이동했는데, UA에 Android를 달고 오면서 `intent:`는 다룰 줄 모르는 것들이 있었습니다 —
검색엔진의 렌더러와 성능 측정 도구가 그렇습니다. 이동하려는 순간 문서가 통째로
사라져 `document.body`조차 남지 않았고, 빈 화면이 색인되고 측정은 '한 번도 그리지
않았다'로 끝났습니다. UA로 크롤러만 골라내는 길도 있지만 이름을 대지 않는 크롤러는
못 거르고, 무엇보다 사람과 기계에 다르게 굴 이유가 없어 그러지 않았습니다.
밖에서 온 링크는 App Links가 이미 브라우저를 거치지 않고 앱을 엽니다.

### 서명 키를 바꾸면

`assetlinks.json`의 지문도 같이 바꿔야 합니다. 안 그러면 확인이 깨지고 링크가
브라우저로 돌아갑니다. 지금 지문은 이렇게 확인합니다:

```bash
apksigner verify --print-certs app/build/outputs/apk/release/app-release.apk
```

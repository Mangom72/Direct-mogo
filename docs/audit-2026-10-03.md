# 9.9 기능·안정성 점검

사용자가 보고한 9.8의 Drive `StorageBackendContentProvider Permission Denial`과
재연결 뒤 0B 파일, 그리고 제시한 37개 항목을 현재 코드와 대조했다.
오류의 실제 문서 URI·반환 Intent·전체 스택은 확보하지 못했다. 따라서 아래의
SAF 결함은 확인했지만, 해당 Drive 내부 URI가 어느 경로에서 만들어졌는지는
확정하지 않는다. 실제 Google Drive 계정의 동기화와 두 실기기 동시 수정은
이 환경에서 시험하지 않았다.

## 재현과 수정

`SafFixtureProvider`는 테스트 APK에만 들어가는 DocumentsProvider다.
`SafGrantActivity`가 Activity 결과로 실제 URI grant를 전달한다. `SafCheck`에서
읽기/쓰기 영구권한 확보, 읽기만 반환된 결과 거절, 기존 연결 보존, 영구권한
해제 뒤 연결 정리를 확인했다. provider가 파일을 truncate하여 **0B로 만든 뒤
쓰기 실패**를 반환하도록 해서, 기존 정상 JSON과 새 전체 상태가 내부
AtomicFile 사본에 남는 것도 확인했다. 이것은 Drive 자체의 재현을 대신하지 않는다.

앱은 자동백업 쓰기 전에 내용을 다시 읽고 비교한다. 빈/손상된 기존 백업은
자동으로 덮어쓰지 않는다. 직접 만든 새 빈 문서만 최초 쓰기를 허용한다.
`last-good.json`은 덮어쓰기 전 정상 파일이고 `pending.json`은 쓰려던 앱 상태다.
백업 화면의 **자동 백업 복구 사본 → 살펴보기**에서 이전 정상 파일을 합칠 수 있다.
앱의 현재 전체 사본은 내보내기와 웹 저장소가 비었을 때의 복구에 사용한다.
내부 사본은 앱 삭제/데이터 삭제까지 견디는 별도 클라우드 백업은 아니다.

| 번호 | 항목 | 판정·처리 |
|---|---|---|
| 1 | Drive provider Permission Denial | 실재하는 사용자 오류. 반환 URI 출처는 미확정. 2~4의 결함을 수정했고 권한 오류 시 연결 해제·재선택 안내를 한다. 실제 Drive 재현은 미실시. |
| 2 | 영구권한에 고정 READ/WRITE | 수정. 결과 Intent의 실제 READ/WRITE만 추린다. 자동백업에는 두 권한이 모두 필요하며, 확보·persisted 목록 확인 전 연결을 저장하지 않는다. |
| 3 | 영구권한 실패 뒤 AUTO_URI 저장 | 수정. 실패하면 즉시 반환하며 새 URI를 저장하지 않는다. 기존 정상 연결은 유지한다. |
| 4 | 오래된 AUTO_URI | 수정. 실제 persisted 목록과 URI·읽기·쓰기를 대조한다. 권한이 없으면 연결과 비교 기준을 해제하고 재선택을 안내한다. 연결 교체 때 이전 영구권한도 놓는다. |
| 5 | 자동백업의 TIMES 누락 | 수정. 브리지 payload와 네이티브 백업 모두 times·records를 담는다. 구형 v1 파일도 읽는다. |
| 6 | 긴급복구의 부분 상태 | 수정. 일반 백업과 동일한 변환을 사용하고 내 과목·푼 날·시간·점수·오답·테마를 복원한다. 복구 선택 전에 빈 웹 상태를 네이티브로 보내지 않는다. 스크롤 위치 등 기기 UI 설정은 백업 범위가 아니다. |
| 7 | 저장 파일명과 뷰어 탐색 불일치 | 수정. 사람이 읽는 실제 저장 이름으로 먼저 찾고 원본 basename은 구버전 파일 fallback으로 정확히 비교한다. 내부 저장소 fallback도 포함한다. |
| 8 | JPG MIME | 수정. 대소문자를 구분하지 않고 jpg/jpeg를 image/jpeg로 처리한다. PDF/팝업 이미지 읽기에도 jpeg를 포함한다. |
| 9 | 잘못된 UTC Z | 수정. SimpleDateFormat의 시간대를 UTC로 지정한다. 한국 시간대에서도 epoch가 00:00:00Z인지 시험한다. |
| 10 | JS 저장 전 타이머 기록 삭제 | 수정. 안정된 ID로 peek → 웹 저장 → ACK한다. ACK한 ID만 삭제하며 사이에 추가된 기록은 보존한다. 웹 수신 확인을 기억해 재전송이 수동 수정 시간을 덮지 않는다. 옛 페이지용 take도 전달 전에 삭제하지 않는다. 구형 앱의 기존 destructive API 자체는 업데이트해야 바뀐다. |
| 11 | LAST_MODIFIED 없는 provider | 수정. 수정시각 대신 내용 SHA-256을 비교한다. 복귀 때와 실행 중 60초마다 읽는다. 백그라운드에서는 폴링하지 않는다. 즉시 동기화나 Drive 서버 업로드 완료를 보장하지 않는다. |
| 12 | 직접 truncate/write | 완화. 정상 파일·새 상태를 내부 AtomicFile에 먼저 보관하고 닫은 뒤 다시 읽어 검증한다. 선택한 단일 SAF 문서에는 공통 원자적 교체 API가 없으므로 원격 파일의 원자성은 보장하지 못한다. |
| 13 | 두 기기 동시 수정 | 완화. 쓰기 직전 재읽기 후 달라졌으면 병합한다. 마지막 재읽기와 쓰기 사이의 경쟁은 남으며, SAF에 revision/CAS가 없어 완전한 충돌 제어는 아니다. |
| 14 | FloatService 종료/다운로드 경합 | 수정. 종료 상태와 로드 세대가 일치하는 callback만 paper에 접근한다. 종료 때 큐를 비우고 worker를 중단한다. |
| 15 | 큰 이미지 원본 디코딩 | 수정. 먼저 크기를 읽고 power-of-two sampling으로 400만 픽셀·한 변 4096 이하를 목표로 디코딩한다. 일반 이미지 해상도는 유지한다. |
| 16 | 팝업 타이머 탭 즉시 정지 | 수정. 탭은 메뉴만 열며 일시정지/이어서/끝내기는 메뉴에서 선택한다. 에뮬레이터에서 탭만으로 시간이 멈추지 않는지 확인했다. |
| 17 | 네이티브 bottom sheet 높이 | 수정. 뷰어 시트를 화면 높이 안의 ScrollView로 감싼다. 모든 실기기/가로모드 조합의 시각 검증은 미실시. |
| 18 | Float 핵심 버튼 30dp | 수정. 주요 버튼과 타이머의 터치 영역을 48dp로 키운다. 바 높이와 접힌 폭도 함께 계산한다. |
| 19 | PDF timer chip 터치 영역 | 수정. 최소 48×48dp와 중앙 정렬을 준다. |
| 20 | button만 Tab trap | 수정. 링크·입력·선택·textarea·tabindex를 포함하고 숨김/비활성/inert는 제외한다. 기록 입력 폼도 시험했다. |
| 21 | lens focus trap | 수정. lens에도 같은 trap을 적용한다. |
| 22 | modal 배경 inert | 수정. 최상단 modal 외 body 자식을 inert 처리하며 닫힐 때 복구한다. 접근성 기기별 읽기 순서는 별도 확인 필요. |
| 23 | openLog의 늦은 응답 | 수정. 시작 당시 loading 노드와 현재 시트를 대조해 다른 화면에 응답을 쓰지 않는다. 닫고 백업을 연 뒤 늦은 응답을 돌려주는 회귀 시험을 추가했다. |
| 24 | 네이티브 완료 callback 화면 경합 | 수정. 저장/공유 시작 당시 DOM과 현재 시트를 대조한다. 옛 버튼을 갱신해도 새 시트 메시지는 덮지 않는다. 웹은 같은 종류의 중복 작업을 막고 네이티브 파일 작업도 한 개씩 받는다. |
| 25 | 31일의 월 이동 overflow | 수정. 1일로 옮긴 뒤 월을 바꾸고 마지막 날짜로 제한한다. 실제 PageUp으로 2026-03-31 → 02-28, PageDown으로 03-28을 확인했다. |
| 26 | 300~320px 회차 액션 | 수정. 360px 이하에서는 액션을 두 열로 줄바꿈한다. 300px 페이지 가로 넘침을 시험했다. |
| 27 | Float 큰 시스템 글꼴 | 수정·부분 검증. 바 높이를 글꼴 크기에 맞추고 펼친 도구 줄은 가로 스크롤한다. API36 에뮬레이터 font scale 1.0/2.0에서 최소화된 창·테두리·시간·버튼이 들어오는 것을 측정했다. 모든 기기·분할 창 조합은 미실시. |
| 28 | Float 기호 버튼 이름 | 수정. 자료 목록·팝업 최소화/펼치기·닫기·타이머 조작 이름을 지정한다. |
| 29 | 비동기 상태 live region | 수정. sheetNote를 role=status, aria-live=polite, aria-atomic=true로 지정한다. |
| 30 | 겹친 modal 스크롤/포커스 | 수정. 최상단 modal 기준으로 잠금·inert를 한곳에서 계산하고 남아 있는 modal 안으로 포커스를 돌린다. 닫기 순서를 lens → sheet → calendar로 맞춘다. |
| 31 | 잘못된 fragment decode | 수정. decodeURIComponent 실패는 없는 공유 데이터로 처리한다. 잘못된 % 링크에서도 초기화되는지 시험했다. |
| 32 | 원격 JS의 강한 Native Bridge | 조건부 위험 유지. 프로젝트 https 출처·경로 제한, 외부 frame 이동 차단, CSP가 있지만 해당 출처/배포가 탈취되면 native bridge 신뢰도 깨진다. 이번 수정은 bridge를 로컬 패키지나 origin 검증 메시지 API로 전환하지 않는다. |
| 33 | deleteSaved 확인이 웹에만 있음 | 수정. 네이티브 확인 창에서 승인한 뒤 삭제한다. 내부 자동백업 복구 폴더는 전체 삭제 대상에서도 제외한다. |
| 34 | Bridge 입력·작업량 | 강화. setSolved/백업 크기 제한, 저장 요청 64KiB·파일 16개 제한, 파일 작업 동시 1개, 자동쓰기 요청 합치기를 추가한다. 기존 다운로드당 64MiB 한계와 URL/파일명 검사도 유지한다. 출처 탈취로 정상 크기 요청을 계속 보내는 공격까지 해결한 것은 아니다. |
| 35 | 외부 ACTION_VIEW scheme | 수정. main frame의 외부 이동은 https만 전달한다. custom scheme/intent/javascript/file 등은 막는다. 브라우저의 사용자가 누르는 앱 열기 링크는 유지한다. |
| 36 | Actions write token·Python 공급망 | 검토 완료, 현 구조 유지. action SHA와 dependency 버전은 고정돼 있지만 artifact hash pinning과 설치 단계의 write credential 격리는 없다. 배포/수집 push 자격증명 분리와 전체 transitive hash 잠금은 별도 강화 항목이다. 공격이 재현된 취약점으로 확정하지 않는다. |
| 37 | 넓은 FileProvider 경로 | 검토 완료, 현 구조 유지. 동적 이름의 기존 저장 폴더가 external/files root 아래에 있어 단순 축소하면 기존 파일 공유가 깨진다. URI 생성 전 파일명 검사와 실제 파일 선택을 유지한다. 새 하위 폴더 구조로 이관한 뒤 제한하는 강화 작업은 미포함. |

## 함께 반영한 기능

최소화된 팝업은 타이머의 실제 글자 폭과 버튼 터치 영역에 맞춰 창·테두리가
같이 늘고 줄어든다. 10분 추가는 타이머 메뉴와 알림에서 제거했다. 회차의
풀이 기록 버튼에서 분·초, 점수, 틀린 문제 번호를 수정한다. 0점과 오답 없음도
저장하며, 기존 v1 백업과 알 수 없는 과목의 풀이 기록을 보존한다.

## 검증 방법과 범위

- 웹: 고정된 requirements 환경에서 `python3 tests/run.py`. 39개 중 WebKit은
  로컬 라이브러리 부재로 건너뛰며 나머지 38개를 실제 실행한다. 생성 안정성,
  CSP, 폰트와 웹/위젯 대조를 포함한다.
- Android: 저장소 Wrapper로 `testDebugUnitTest lintDebug assembleDebug`. JVM 36개
  실패 0개, lint 오류 0개(경고 53개).
- SAF: `assembleDebugAndroidTest` 후 디버그 앱과 test APK를 설치하고
  `adb shell am instrument -w kr.gijul.direct.test/kr.gijul.direct.SafCheck`.
  테스트용 provider/Activity는 release APK에 포함되지 않는다.
- 팝업: API36 에뮬레이터에서 동작 중/정지/초과 시간을 바꿔 실제 View·WindowManager·
  GradientDrawable의 너비와 자식 배치를 측정했다. `FloatCheck` runner를
  `-PgijulRunner=kr.gijul.direct.FloatCheck`로 빌드해 실행한다. 테스트 에뮬레이터에서
  ActivityThread 확인에 필요한 hidden_api_policy만 임시 허용하고 시험 후 복구한다. font scale 1.0/2.0 모두 통과했다.
  에뮬레이터 System UI ANR 대화상자가 캡처에 보였으므로 캡처를 전체 기기 안정성
  통과 근거로 쓰지 않는다. 앱 AndroidRuntime 크래시는 발견되지 않았다.
- 실제 Google Drive, 두 실기기 동시 쓰기, TalkBack 및 모든 작은 화면/가로모드의
  시각 검증을 전체 성공으로 보고하지 않는다.

SAF의 반환 권한·이동/삭제 후 재선택은
[Android 문서 접근 지침](https://developer.android.com/training/data-storage/shared/documents-files?hl=en)을,
provider별 쓰기 모드와 한계는
[ContentResolver API](https://developer.android.com/reference/android/content/ContentResolver)를,
원격 bridge 신뢰 경계는
[Android WebView native bridge 지침](https://developer.android.com/privacy-and-security/risks/insecure-webview-native-bridges)을 대조했다.

# 종이 OMR 촬영·채점 기능 검토

검토일: 2026-10-03. 기준: `773cfa5`, 앱 10.1. **기능적으로 가능하다.**
답지의 정답·배점을 확보하고, 지원하는 종이 OMR 양식을 촬영해 답을 읽은 뒤,
사용자가 애매한 마킹을 확인하면 기존 점수·틀린 번호 기록에 반영할 수 있다.
처음에는 자체 연습용 양식처럼 좌표가 알려진 답안지를 지원하고, 검증한 양식을
추가하는 방식이 적합하다. 모든 시판 답안지를 자동으로 읽는 기능은 별도 범위다.

초기 조사는 **가능성 조사, 합성 이미지 실험, 디자인 시안**이었다.
2026-10-03 후속 작업에서 교육청 공개 수능 견본의 직접 입력·문서 스캔 진입·
고정 양식 사진 판독·점수 기록을 구현했다. 현재 기능·제약은 [답안 입력·채점](omr.md)을 따른다.
이 문서의 초기 합성 실험 수치를 실물 촬영 정확도로 해석하지 않는다.

## 실제 자료에서 확인한 범위

저장소의 `data/D*/*.json`을 집계하면 과목·회차 자료 5,110건 중 PNG 답지는
2,136건, JPG 답지는 1,048건, 답지 링크가 없는 자료는 1,926건이다.
**3,184건은 이미지 링크가 있다는 뜻이며, 인식 성공 건수가 아니다.**

| 확인 대상 | 결과와 한계 |
| --- | --- |
| 답지 PNG 10개, 과거 JPG 1개 | 선택형 원문자·수학 숫자 답·표 배치 차이를 확인했다. PNG 10개 응답에는 CORS 허용 헤더가 있었다. 전체 호스트·PDF·JPG에 대한 보장은 아니다. |
| 최근 해설 PDF 4개 | 국어 45개, 영어 45개, 수학 30개, 생명과학Ⅰ 20개의 문항-정답 쌍을 텍스트에서 추출했다. 생명과학Ⅰ은 정답 이미지와 전 문항 대조했다. 나머지는 추출 개수 확인이며 전 답 수동 검증은 아니다. |
| 생명과학Ⅰ 문제 PDF 1개 | 문항 좌표와 `[3점]`을 연결하고 4쪽 전체를 눈으로 대조했다. 3점 문항은 2·5·7·11·13·14·15·18·19·20번, 나머지는 2점으로 합계 50점이다. |
| 이미지 전체에 일반 OCR 적용 | 로컬 Tesseract 영어 모델의 표·원문자 판독에는 오독이 있었다. 이 결과로 ML Kit나 다른 모델의 정확도를 판단하지는 않았다. |

검토 예시는 **2026년 9월 2일 시행(2027학년도 9월 모평)**이다.
생명과학Ⅰ의 [정답 이미지](https://wdown.ebsi.co.kr/W61001/01exam/20260902/mobile/h3_m_g_bio1_ans_45HY71KP.png),
[해설 PDF](https://wdown.ebsi.co.kr/W61001/01exam/20260902/go3/g_bio1_hsj_K83D3XN1.pdf),
[문제 PDF](https://wdown.ebsi.co.kr/W61001/01exam/20260902/go3/g_bio1_mun_DE4O4J64.pdf)를 대조했다.
초기 시안의 제출 답은 가상 예시이며 3·15·19번을 틀리면 2+3+3점이 빠져 **42/50점**이다.
원본 시험 자료·공식 답안지 PDF는 저장소에 넣지 않았다. 후속 기능의 공식 견본 배경 이미지는 별도로 포함한다.

## 답지 인식과 종이 OMR 판독은 두 단계다

**정답표 확보:** 해설 PDF에 텍스트가 있으면 문항 번호와 정답을 먼저 추출한다.
이미지 답지만 있으면 표의 행·열을 분리하고 숫자·원문자를 읽는다.
중복 번호, 누락, 문항 수, 선택형 범위 1~5, 단답형 범위를 검증하고, 과목·선택과목·
시행일·시험지 유형까지 맞춰야 한다. 답지가 없는 자료는 지원 불가로 표시하거나
사용자가 확인한 정답표를 입력하게 해야 한다. 인식한 정답표에도 검토 과정이 필요하다.

**배점 확보:** 답지에 정답만 있고 배점이 없을 수 있다. 문제 PDF의 문항별 배점을
따로 추출·검증해야 하며, 맞힌 개수에 일정 값을 곱해 점수를 만들면 안 된다.
만점이 100점이면 0~100, 50점이면 0~50의 **정수 원점수**를 기록한다.
배점이 확인되지 않으면 맞힌 개수만 보여 주고 점수 반영은 막는다.
현재 입력 화면의 수학 숫자 마킹에서도 이 상태를 직접 체험할 수 있다.

**종이 판독:** 양식 식별 → 모서리/정렬 표식 검출 → 기울기·원근 보정 → 답란별
밝기 보정 → 채움 정도 판정 → 흐린·중복·미응답 확인 순서다.
검은 마킹을 읽는 OMR과 글자를 읽는 OCR을 구분해야 한다.
원근 보정과 밝기에 따른 이진화는 OpenCV가 제공하는 기본 방법을 쓸 수 있다.
이는 구현 방향이며 실제 기기 정확도가 검증되었다는 뜻은 아니다.
([원근 변환](https://docs.opencv.org/4.x/da/d6e/tutorial_py_geometric_transformations.html),
[임계값 처리](https://docs.opencv.org/4.x/d7/d4d/tutorial_py_thresholding.html))

수학의 숫자 답은 백·십·일 답란을 따로 판독해 0~999의 정수로 조합한다.
`006`은 6으로 비교하되 **미마킹을 숫자 0으로 바꾸지 않는다.** 자릿수별 중복·흐림·
미마킹은 확인 대상으로 남기고, 지원 양식의 앞자리 표기 규칙을 따른다.
선택형/단답형의 문항 위치와 전체 문항 수는 과거 시험까지 고정하지 않고 양식별로 둔다.

## 촬영 판독 원리 실험

자체 20문항 양식과 같은 답란 좌표를 가진 합성 이미지를 만들었다.
검은 사각 정렬 표식 네 개를 자동으로 찾고 원근 보정한 뒤 각 답란을 분류했다.
세 가지 원근 × 그림자 유무 × 흐림 유무, JPEG 품질 80의 **12개 조건 모두**에서
20문항의 정상·흐림·중복·미응답 분류가 예상과 일치했다.
모서리 표식 하나를 지운 이미지는 거부했다.

**이 결과는 고정 양식의 통제된 합성 실험이다.** 실제 휴대폰 사진, 인쇄 오차,
종이 구김, 지우개 흔적, 연필·볼펜 차이, 공식 수능 답안지 인식은 검증하지 않았다.
실험 수치를 실제 사용자 인식률로 표시해서는 안 된다. 시안의 인쇄 양식 역시
실제 인쇄·촬영 검증을 마치기 전에는 지원 양식이라고 안내하지 않는다.

실험 코드: [photo_probe.py](design/omr/research/photo_probe.py).
웹·Android 의존성과 분리한 연구 환경에서 저장소 루트 기준으로 재현한다.

```bash
python3 -m venv .git/codex-omr-venv
.git/codex-omr-venv/bin/python -m pip install -r requirements/omr-probe.txt
.git/codex-omr-venv/bin/python docs/design/omr/research/photo_probe.py
```

결과 JSON과 자체 합성 이미지는 `.git/codex-evidence/omr-photo/`에 저장된다.
원본 시험 파일·개인 사진·계정 정보가 필요하지 않으며 저장소에도 올라가지 않는다.

## 초기 설계와 후속 과제

1. **첫 지원 양식·정답표 검증.** 자체 탐구 20문항 양식과 검증한 한 회차부터 시작한다.
   과목·시험지 유형이 다른 사진, 지원하지 않는 양식, 잘린 사진은 채점을 막고 다시 촬영하게 한다.
2. **Android 촬영·사진 선택과 로컬 판독.** 촬영 취소·권한 거부·회전·앱 종료를 처리하고,
   큰 이미지는 제한된 크기로 읽는다. 사진 원문·개인 식별 영역은 처음부터 서버로 보내지 않는
   설계가 적합하다. 이 정책은 구현 시 개인정보 처리방침과 일치시켜야 한다.
3. **PDF 텍스트 추출 또는 이미지 정답표 OCR.** 현재 `PdfRenderer`는 렌더링에 쓰고 있다.
   PDF.js 같은 별도 텍스트 추출 경로 또는 네이티브 추출기를 검토해야 한다.
   PDF.js는 정적 웹에서 라이브러리로 사용할 수 있지만 크기·worker·CSP·WebView 호환성을
   확인하고 버전을 고정해야 한다. 새 번들러를 도입할 필요는 없다.
   ([PDF.js 공식 예제](https://mozilla.github.io/pdf.js/examples/))
4. **필요한 글자 인식 모델을 정한다.** Android ML Kit는 기기 내 이미지 OCR 후보다.
   공식 설치 지침의 API 23 이상 조건은 현재 앱의 `minSdk 24`와 맞는다.
   모델을 앱에 포함하는 방식과 처음 다운로드하는 방식의 오프라인 동작·크기는 다르다.
   OCR 모델은 정답표/양식 식별에 쓰고, 마킹 판독을 대신한다고 가정하지 않는다.
   ([ML Kit Android 지침](https://developers.google.com/ml-kit/vision/text-recognition/v2/android))
5. **확인 후 기록 반영.** 사용자가 검토한 정수 점수·틀린 번호만 기존 `records`에 반영하고,
   기존 `times`와 푼 날을 보존한다. 재채점으로 이전 기록을 덮을 때는 변경 내용을 보여 준다.
   원본 사진·문항별 답·판독 초안은 별도 저장소가 필요하다. 클라우드에 넣을 경우에는
   새 데이터 규칙·동기화·백업 호환성과 개인정보 정책을 함께 설계한다.

**홀수형·짝수형 구분은 필수다.** 기존 푼 회차 열쇠는 홀짝을 합치지만 채점의 정답 순서는
달라질 수 있다. 정답표 캐시와 OMR 세션은 원본 유형·선택과목·양식 버전·정답표 버전을
포함한 별도 식별자를 사용해야 한다. 기존 회차 열쇠로 정답표를 재사용하면 안 된다.
옛 앱의 브리지 인자 수·백업 v1은 유지하고 새 기능에는 새 메서드와 구형 앱 안내를 둔다.

## 현재 디자인과 검증 범위

사용자 지정에 따라 교육청 공개 수능 견본 여섯 양식을 실제 배경으로 사용한다.
원본 답란과 견본 표시를 유지하고 시험명·연도·과목·영역·교시는 학습용으로
덧붙인다. 기존 기출 직행의 글꼴과 색을 유지한다.

입력 방식 선택 → 직접 마킹 또는 스캔·모서리 보정 → 답안 확인 → 정답·배점
확인 → 결과 → 기록 순서다. 앱·웹과 체험 화면은 같은 입력 모듈을 사용하며
체험에서는 실제 기록을 저장하지 않는다. 현재 검증 내용과 제한은
[답안 입력·채점](omr.md)을 따른다.

실물 촬영 검증에는 인쇄 후 여러 휴대폰으로 촬영한 자료가 필요하다.
기울기·회전·그림자·반사·저해상도·잘린 모서리·중복/희미한 마킹·지운 흔적을
포함하고 수학 0/한 자리/세 자리·미마킹·잘못된 과목·홀짝형을 대조해야 한다.
합성 이미지 통과를 실물 촬영 정확도로 표시하지 않는다.

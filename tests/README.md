# 시험

```bash
pip install playwright "fonttools[woff]" brotli && playwright install chromium
python3 tests/run.py              # 전부 (3분 남짓, 29종)
python3 tests/run.py sw stale     # 이름에 그 말이 든 것만
python3 tests/run.py -v           # 출력까지 그대로
```

서버는 `run.py`가 한 번 띄워 모두가 나눠 씁니다. 크로미움 경로도 스스로 찾으므로
따로 맞출 것이 없고, 필요하면 `GIJUL_CHROME`으로 덮어쓸 수 있습니다.

## 합격 판정

종료 코드가 0이 아니면 실패입니다. 더해서, 출력에 아래 표시가 있으면 실패로 봅니다.

```
★        무엇이 어긋났는지 적는 자리
전체: 실패 · 문제: 있음 · ERRORS: [ · 기대대로: False
```

시험이 사람이 읽을 수 있게 결과를 적어 온 방식을 그대로 판정에 쓰는 것입니다.
새 시험도 이 표시를 따르면 됩니다. **기대한 오류는 걸러서 적으십시오** — 예를 들어
`test_send`는 내려받기를 일부러 막는 대목이 있어, 그때 나는 네트워크 오류를 빼고
적습니다. 그러지 않으면 정상 동작이 실패로 잡힙니다.

| `test_offline_save` | 회차를 통째로 받아 앱 폴더에 보관하는 흐름 |

| `test_sw` | 서비스 워커 — 미리 담기, 오프라인, 캐시 상한, 셸 갱신 감지 |
| `test_stale` | 새로고침을 **닫은** 뒤 다시 확인하면 사실대로 말하는가 |

| `test_toapp` | 자동으로는 앱에 넘기지 않고, 누를 때만 넘어가는가 |
| `test_apkbar` | 첫 그림부터 떠 있는 안내 막대가 뒤에 오는 알림을 삼키지 않는가 |

| `test_fields` | 회차 `id`가 유일한가, `type`·`form`·`schoolYear`·`aliases`가 서로 맞는가 |

| `test_scv` | 회차 이름의 EBSi 링크가 **실제로 열리는 회차에만** 걸리는가, 바깥으로 나가는 것이 보이는가 |

## 왜 `test_glyphs`가 따로 있는가

`tools/build_fonts.py --check`는 **자기가 방금 모은 목록**과 글꼴을 견줍니다.
글자를 모으는 규칙 자체가 틀리면(주석을 걷어내는 부분이 지나치게 걷는 경우가
그렇습니다) 스스로를 통과시킵니다. `test_glyphs`는 앱을 학년·과목군·과목마다
돌리고 과목 페이지 50장을 훑어 **실제로 그려진 글자**를 모아 견줍니다.
글자 목록을 손볼 때는 이쪽을 보십시오.

## 여기 있는 시험은 대부분 겪은 뒤에 쓴 것입니다

`test_recv6`은 여섯 과목을 보냈는데 하나만 도착한 일에서, `test_stale`은
새로고침을 닫으면 그 뒤로 계속 "최신입니다"라고 답하던 일에서, `test_apkbar`는
앱 설치 안내가 과목 받기 질문을 덮어 다섯 과목이 사라진 일에서 왔습니다.
`test_dday`의 자정 넘김은 앱을 접어 두었다가 이튿날 아침에 폈더니 D-day가
어제 숫자 그대로였던 일에서 왔습니다.
같은 일이 다시 나지 않게 하는 것이 이 폴더의 목적입니다.

`test_scv`는 겪기 전에 쓴 몇 안 되는 시험입니다. EBSi는 없는 회차를 물으면
404를 주지 않고 **말없이 첫 화면으로** 보냅니다. 그래서 링크를 잘못 걸어도
화면에서는 멀쩡해 보이고, 누른 사람만 자기가 왜 엉뚱한 데 왔는지 모른 채
돌아옵니다. 이건 일어난 뒤에 알아차릴 방법이 없어서 미리 못박았습니다.

## CI에서는 두 갈래로 돕니다

**자료 갱신**(`refresh-data.yml`)은 `test_fields`와 `test_stable` 둘, 그리고
`test_dday --date`를 돌립니다.
이 둘은 **브라우저도 서버도 쓰지 않아** 몇 초면 끝나고, 그 작업이 실제로 낼 수 있는
잘못(회차 이름표 겹침, 시험 종류와 출제 기관 어긋남, 학년도 오류, 과목 별칭 충돌,
재현되지 않는 빌드)을 덮습니다. 사람이 보지 않는 채로 커밋이 나가므로 여기서
실패하면 커밋 단계로 가지 않습니다. 크로미움을 받는 데만 1~2분이고 실행에 3분이
더 드는 나머지를 여기서까지 돌리지는 않습니다 — 그 작업이 건드리는 것은 자료뿐입니다.

`test_dday --date`는 자료와 무관하게 **매일 봐야 해서** 여기 붙어 있습니다. 수능
시행일은 관례(11월 13~19일 목요일)로 셈하므로 평소에는 손댈 것이 없지만, 시험이
연기되거나 평가원이 관례를 벗어나 공고하면 화면은 그것을 모른 채 옛 관례대로
셉니다. 그래서 셈한 날을 한국어 위키백과의 학년도별 인포박스와 대조하고, 어긋나면
실패합니다 — `SUNEUNG_MOVED`를 채울 때라는 신호입니다.

**위키백과 값을 화면에 쓰지는 않습니다** — 누구나 고칠 수 있는 문서라 그것을
그대로 믿을 수는 없습니다. 닿지 못하면 그냥 넘어갑니다. 인포박스를 읽는 규칙과
셈 자체는 망 없이 `test_dday` 안에서 2016~2027년 실제 시행일과 견줍니다.

자료 커밋 뒤에 두어서, 날짜가 어긋났어도 그날의 자료는 그대로 나가고 워크플로만
빨갛게 뜹니다.

**화면 쪽**(`tests.yml`)은 `index.html`·`sw.js`·`s/`·`tools/`·`tests/`가 바뀐 채로
main에 올라갈 때 29종을 전부 돌립니다. 실패하면 그때의 화면 그림이 artifact로
남아, 손에서 재현되지 않는 실패도 눈으로 볼 수 있습니다.

어느 쪽이든 CI는 마지막 그물입니다. 고친 자리에서 `python3 tests/run.py`를 먼저
돌리는 편이 훨씬 빠릅니다.
